# MiniMax Music 3 音乐提示词规范（music-prompt）

适用于「音乐生成」（MiniMax Music 3）工作流。把用户的一句话音乐需求、粗略描述、带歌词的脚本整理成**可直接用于生成的结构化 Caption**，再填入工作流的 Caption 参数并调用生成。

## 输入
- **Caption**：自然语言的音乐描述（必填）。
- **Lyrics**：可选歌词，可能含 [段落] 标签。
- 附加约束：时长、风格、想排除的元素、创作方向。

- 只用歌词推断**情绪基调与叙事强度**；**不要**引用、转述、概括或复现歌词内容。
- 只有方括号标签（[Verse] [Chorus]…）是可执行的**结构/人声/制作指令**，其余歌词文字一律不进入 Caption。

## 约束优先级（按序）
1. 用户**明确**要求与排除项
2. 歌词标签内的**段落局部**指令
3. Caption 描述中的强暗示
4. 保守的音乐默认

- 段落标签只改变该段**局部配器/编曲**，不推翻整曲的全局流派；段落标签与硬性排除冲突时，保留用户的排除项。
- 两条显式要求冲突时，取更具体、更靠后的那条；无法判断就做最小的、音乐上合理的折中。
- **绝不擅自反转**：明确的音色性别、纯音乐要求、速度上限、指定乐器、禁用元素。
- 不要编造精确调性、拍号、歌手音域或过细的生产技法——描述足够即可，不硬凑 BPM/Key。

## 写成三段结构
最终 Caption 依次包含三个顶层部分（结构标题可中英皆可，内容语言跟随用户）：

### 1. 全局元数据 Global Metadata
流派与子流派、风格定位、速度与律动、情绪推进弧线、整体声学与制作特征。
BPM 只在用户明确给出或能强推出时写精确值，否则用区间或「中速/偏慢」这类定性描述。

### 2. 人声细节 Vocal Details
- 有人声时：主唱配置、音色、音域/唱法、情绪语气、和声/伴唱、克制的演唱声效。
- 纯音乐时：明确写 `instrumental / 纯音乐`，并指出承担主旋律的乐器或声部。
- 不要虚构歌词主题，不要复述歌词。

### 3. 编曲 Arrangement（分段时间线）
- 优先采用用户歌词给出的段落结构；没有则按风格选合适结构，例如：Intro → Verse → Pre-Chorus → Chorus → Verse → Chorus → Bridge → Final Chorus → Outro。
- 对每一段说明：谁进入/退出/变化/增强；乐器生命周期连续；转场有音乐依据；全曲有能量起伏，而不是静态乐器清单或术语堆砌。

## 歌词段落标签
- 方括号标签（[Intro] [Verse] [Pre-Chorus] [Chorus] [Bridge] [Solo] [Outro] [Hook]）→ 必须落到对应段落的编曲描述里。
- 圆括号（(Ooh) (Whispered) (Fade out)…）→ 作为该处的演唱/声效提示，可保留在对应段内。

## 校验后返回
返回前自查：
- 用户显式约束全部保留；
- 每个有效段落标签都出现在对应段落；
- 没有引用/转述歌词、歌名、track id；
- 纯音乐仍是纯音乐；音色性别不被推翻；
- 三个部分齐全；时间线可读；乐器进出合理；
- 没有编造精确 BPM/调性/技术细节；
- Caption 具体到能引导生成，但不冗长成小作文（参考 250~450 词或等价中文字数）。
任一项不过，修订一次后只返回修正结果。

## 输出与调用
- Caption 语言跟随用户（中文用户默认中文，结构标题可用英文或中文均可）。
- 不输出歌名、track id、推理过程或内部草稿。
- 完成后：把 Caption 填入「音乐生成」工作流的 **Caption** 参数；若需保留歌词，把带段落标签的歌词填入 **Lyrics** 参数；时长按用户要求填（没有则默认），然后调用该工作流生成。
